## Потоки и владение станциями
1. UI вызывает `loadFileAsync` -> задание в `ThreadPool` (декодирование, без касания аудиопотока).
2. Готовый `StationBuffer` попадает на message-поток (`callAsync`), где создаётся **новый** `StationSnapshot`
   (копия предыдущего + изменённый слот) и атомарно публикуется (`current_`).
3. Аудиопоток в начале блока вызывает `acquire()`: читает `current_`, пишет `inUseSerial_`. Никаких блокировок/аллокаций/refcount.
4. Таймер (1 Гц) на message-потоке вызывает `reclaim()`: освобождаются снимки со `serial < inUseSerial_`.
   Деструкторы больших буферов никогда не выполняются на аудиопотоке.

## Цепочка RadioEngine (на каждый сэмпл)
1. Настройка сглаживается (постоянная времени 3-253 мс по `tuningSpeed`).
2. Сила каждой станции `s_i` (гаусс); амплитуда станции = `s_i`, при суммарной мощности > 1 - нормировка (равная мощность).
3. Качество приёма `Q = max(s_i) * (0.3 + 0.7*reception)`, сглаживается 25 мс; стартует сразу с целевого значения.
4. ANALOG: флаттер амплитуды (глубина от `1-Q`), HP 30->280 Гц и LP 18 кГц->2.5 кГц по Q; CLEAN: почти не портит звук.
5. Сатурация (выровнена по громкости) -> шум (статик, всплески, потрескивания; уровень по Q и ручке Noise) -> стереобаза M/S
   (сужается при плохом приёме, MONO схлопывает S) -> выходной gain -> опциональный мягкий потолок -> защита от NaN/Inf.
6. Нет станций (или все недоступны по частоте) -> гейт шума закрывается: тишина, а не мусор.
7. Вход плагина не используется; станции звучат сами. Позиции воспроизведения свободно идут вне зависимости от транспорта хоста.

Станции: цикл с кроссфейдом на границе (равная мощность, считается при чтении, без задержки и без лишней памяти),
one-shot с коротким затуханием в конце. Замена станции: старый вклад затухает ~2 мс, новая появляется за 10 мс.
Буфер с другой частотой дискретизации, чем у движка, считается недоступным (тишина) до прихода пересчитанного.

Управление частотой: ручка (параметр) -> SEARCH/SCAN/LOCK (команды из UI) -> результат поиска записывается в параметр
таймером на message-потоке. Движение ручки прерывает поиск; при LOCK ручка игнорируется; UNLOCK возвращает управление ручке.

## Модель настройки
- Диапазон 87.5–108.0 МГц (параметр `frequency`).
- Сила станции `s_i = strength_i * exp(-((f - f_i)/bw)^2)`, `bw = 1.5 * 0.1^selectivity` МГц.
- Две сильнейшие станции смешиваются равномерно-мощностными весами; общий уровень падает при удалении от обеих.
- Reception (параметр) и `s_i` определяют полосу фильтров, уровень шума и нестабильность (этап 3).
- SEARCH/SCAN (этап 3): детерминированный конечный автомат на аудиопотоке, цель - ближайшая станция с `s_i > порог(scanSensitivity)`,
  гистерезис: порог остановки выше порога продолжения.

## Известные ограничения
- JUCE/VST3-часть (процессор, StationManager, CMake, workflow) НЕ компилировалась: JUCE и MSVC недоступны в среде разработки.
- Нет UI для загрузки станций/кнопок (временный Generic-редактор), нет пресетов, нет копирования ассетов в папку проекта.
- Нет «wow & flutter» по высоте тона (флаттер - только амплитудный), нет режима шума «silence/static between» отдельно.
- Скорость поиска = параметр `tuningSpeed` (отдельного параметра scan speed нет).
- Частота дискретизации: пересчёт станций после смены частоты идёт асинхронно; до его завершения станции молчат.
- Нет проверки в DAW.
